# 禅净 交互元素→期望结果 完整映射表（测试基准 v1.2）

> 本文档是所有测试的基准。每个可交互元素都列出：直接结果、间接结果、状态依赖、已知问题。
> 测试时逐项验证，不遗漏。最后更新：2026-09-12（checkpoint v0.9.0）
> v1.2：场景不再覆盖分类；名单与界面语言脱钩；托盘结束=破功；商店壳按标题拦；无管理员提示写死。

## 一、首页（MainPage）

### 1. 场景按钮（工作/写作/学习/会议）— 左键点击

| 项目 | 内容 |
|---|---|
| 元素 | 4个按钮：SceneWork(tag=work)、SceneWrite(tag=write)、SceneStudy(tag=study)、SceneMeeting(tag=meeting) |
| 直接结果 | ① 按钮高亮（苔青背景+白字）；② 愿望框填充场景预设愿望；③ 时长设置为场景预设（ADHD 时 15 分钟）；④ **不改屏蔽页勾选**（空名单才按场景默认补一次）；⑤ 场景摘要更新（分类数读屏蔽页当前勾选） |
| 间接结果 | ① AppServices.CurrentSceneTag 落库；② CurrentWish/CurrentMinutes 更新；③ 编码检测第 3 次走同一套 ApplyScenePreset |
| 状态依赖 | 专注中点场景仍只改愿望/时长预填，不改正在跑的屏蔽 |
| 已知问题 | 无（v0.9.0：分类以屏蔽页为准） |

## 十二、测试策略教训（从bug中总结）

### 教训1：每个方法的每个分支都要验证"副作用"

**bug回顾**：FocusController.Start()有两个分支（有场景/未选场景）。有场景的分支调用了`_blocklist.Apply()`，未选场景的分支漏了。测试只验证了愿望和时长，没验证`IsApplied()`，导致bug溜到真机。

**规则**：
- 每个public方法的每个if/else分支都要有对应测试
- 测试不能只验证"返回值"，必须验证"副作用"：数据库写入、文件写入、状态变更、事件触发
- 开始专注的副作用清单：`_engine.IsRunning=true`、`_blocklist.IsApplied()=true`、系统hosts写入、桌面App拦截生效、`CurrentWish/CurrentMinutes`更新

### 教训2：集成测试必须走"真实入口"，不能直接调底层

**bug回顾**：Flow2专注全流程测试直接调`_engine.Start()`，绕过了FocusController。而bug恰恰在FocusController里（未选场景分支没调Apply()）。

**规则**：
- 集成测试必须模拟用户真实操作路径：用户点按钮→UI层→Controller→Service
- 不能为了"方便"直接调底层Service，否则UI层/Controller层的bug永远测不出来
- 新增的`Flow2_FocusController_WithoutScene_StillAppliesShield`是正确示范：走FocusController，验证完整端到端

### 教训3：UI入口逻辑必须抽到纯服务类才能被测试

**bug回顾**：重构前ToggleFocus在MainWindow.xaml.cs里，是UI代码，传统单元测试很难覆盖。85个自动化测试都没测出快捷键bug。

**规则**：
- 所有"用户入口逻辑"（按钮点击、快捷键、托盘菜单、API调用）必须抽到纯服务类（如FocusController）
- 纯服务类不依赖XAML元素，可被单元测试覆盖
- UI层只做"调用Controller + 导航页面 + 显示结果"，不包含业务逻辑
- FocusController重构后，新增8个单元测试覆盖，以后改坏直接报错

### 教训4：测试用例要从"用户意图"角度写，不是从"代码实现"角度

**bug回顾**：测试写的是"Start_WithoutScene_UsesDefault25Minutes"，只验证了时长。但用户的真实意图是"我没选场景，通过托盘开始专注，抖音应该被屏蔽"。

**规则**：
- 测试名称应该描述用户意图，如"Start_WithoutScene_StillAppliesShield"
- 测试断言应该覆盖用户关心的结果，而不是代码内部状态
- 问自己：如果这个功能坏了，用户最先发现的是什么？那就是最该断言的

### 教训5：自动化测试通过 ≠ 功能正确

**bug回顾**：93个测试全部通过，但真机测试发现抖音没被屏蔽。

**规则**：
- 自动化测试只能覆盖"被断言的部分"，没断言的部分就是盲区
- 每次真机发现bug，第一反应是：为什么自动化测试没测出来？然后补充测试用例
- 测试覆盖率不是看"行数"，而是看"用户操作路径×副作用"的组合覆盖度
